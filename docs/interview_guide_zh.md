# 面试讲解指南

## 30 秒介绍

这是我把大一时期未完成的 Titanic 项目重新工程化的过程。原代码只做到了
部分特征处理，还存在目标泄漏，也没有模型评估。我将它重构成完整 Pipeline，
比较四类分类模型，并发现普通随机分层会把同一家庭或票号的乘客分到训练和
验证两边。因此我增加了家庭—票号分组验证，用一标准误差规则避免过度解读
微小分数差异，最终选择分组表现更稳定的 Extra Trees。模型在 Kaggle 上从
0.77751 提升到 0.78229，项目同时加入了消融实验、解释、测试和结果版本化。

## 为什么这个项目不只是 Kaggle 入门练习

重点不在数据集难度，而在完整解决了这些问题：

1. 从不可运行、未完成脚本迁移到可复现流水线；
2. 识别并修复目标泄漏；
3. 区分普通交叉验证和关联样本分组验证；
4. 不因 0.0007 的均值差异武断选模；
5. 用验证折而非训练集解释模型；
6. 保留提交文件与排行榜成绩之间的可审计关系。

## 常见追问

### 为什么不用准确率最高的随机森林？

随机森林的重复 CV 为 0.8286，Extra Trees 为 0.8279，差异只有 0.0007，
而各折标准差约为 0.02，因此不能认为随机森林真正更好。分组验证中 Extra
Trees 为 0.8238，随机森林为 0.8115，所以我在统计上近似打平的候选模型中
选择了分组泛化更好的模型。

### 为什么需要家庭—票号分组？

同一家庭或同票乘客在年龄、姓氏、票价和生存结果上可能高度相关。如果随机
拆分，模型可能在验证集遇到训练集中某位乘客的近似副本，导致结果偏乐观。
分组验证更接近预测未见家庭的压力测试。

### 原项目的数据泄漏是什么？

原脚本使用 `Survived` 作为输入训练年龄填补模型。预测目标在预处理阶段进入
特征，会使验证结果失真，而且测试集不存在 `Survived`，训练和测试处理方式
也不一致。新版只在各训练折内拟合填补器，不使用目标变量。

### 为什么 Extra Trees 可能比随机森林稳定？

两者都是树的集成。随机森林在每个候选特征中寻找较优切分，而 Extra Trees
还会随机化切分阈值，通常增加单树偏差但降低树之间相关性。在这个小数据集
上，它的普通验证没有明显优势，但分组验证波动和平均表现更好。

### 特征重要性说明了什么？

置换重要性衡量在验证集打乱某个原始字段后准确率下降多少。性别最重要，姓名
通过称谓和长度提供信息，家庭人数和舱位等级也有贡献。这是预测关联，不是
因果结论。

### 为什么不继续刷排行榜？

排行榜反馈也是测试信息。反复根据它修改模型，会逐渐对排行榜过拟合。因此
项目只保留 v1 和一次方法驱动的 v2，把重点放在验证设计和可复现性。

### 如果有更多时间会做什么？

优先做嵌套分组交叉验证，并比较 CatBoost、RBF-SVC 和校准后的软投票；只有
在外层分组验证稳定改善时才保留。不会直接进行大规模网格搜索。

## 可以承认的局限

- 训练样本仅 891 条，指标方差较大；
- 家庭和票号的分组规则是领域假设；
- 测试集没有标签，无法做细粒度线上错误分析；
- Kaggle 得分提升只有 0.00478，改进主要体现在方法严谨性；
- 数据反映特定历史事件，不应迁移到现实人员决策。
